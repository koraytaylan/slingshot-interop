# Plan 0001 — Standalone release interop harness for the Slingshot pair — 🚧 In progress

- **Status:** 🚧 In progress.
- **Goal:** This repository becomes the standalone gate both siblings' release checklists rely on: one command runs the real client executable against the real agent bundle inside rootless Podman containers, with each side pinned by digest to released bytes, owner-supplied candidate bytes, or both, and every result names exactly the bytes it ran.
- **Root cause:** The two siblings change independently and neither can prove the pair still speaks. The only cross-repository tier lives inside the agent repository, runs only when an owner supplies the sibling's executable, and answers from the agent's perspective alone; the client repository has no cross-repository tier at all. A release of either half is a claim about bytes nobody has run against the other half.
- **Approach:** A Bun and TypeScript harness with no framework beyond Bun's own test runner. Prepared inputs are prepared once by named commands that say when they reach the network and verified offline by the gate: the pinned Bun binary, the locked compiler cache, and the digest-pinned container images. Each side has one pinning document with an explicit-absent released slot and an owner-acknowledged candidate slot and six distinct refusals; the harness never builds, fetches, or caches a sibling. Three container roles run on one rootless Podman network per run — the pinned public Sling runtime with the resolved Sling-only bundle installed through the platform's own console, a pinned glibc client runner mounting the supplied release executable and configured through the client's own profile mechanism, and a severance proxy built from the pinned Bun that resets connections at a named point. Scenarios are one file each, discovered from their directory, and prove the exchange-level contract through the real client's own CLI with absolute deadlines and bounded capture: the walking skeleton, a write-then-read round trip, a detached operation followed to a terminal disposition, the agent's declared failure category surfacing unchanged, an authentication refusal with nothing admitted, an oversized result answered by artifact reference and fetched against its declared digest, and a severed submission that lands in the declared unknown outcome and reconciles without resubmitting. One report per run names every byte, so each sibling's release step is: supply the bytes, record the digest, acknowledge, run one command, read one report.
